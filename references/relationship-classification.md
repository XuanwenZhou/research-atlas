# 关系判断

| 类型 | 采用条件 | 不充分依据 |
|---|---|---|
| direct | 明确采用前驱实现、表示、模型或不可缺少结构 | 引用或年代先后 |
| extension | 明确修改扩展前驱框架或解决其具体缺陷 | 同一研究问题 |
| borrow | 明确引入前驱模块、损失、算子或训练机制 | 名称或机制相似 |
| theme | 同方向、机制对照、并行探索，无继承语义 | 不画继承箭头 |

起点为被采用方法，终点为采用者。direct 与 extension 择最能表达论点者，在 basis 解释，不复制同义边；同一对方法已建立 direct/extension/borrow 技术边时，不再重复添加 theme 边。borrow 写清借了什么、在何处使用。

逐边阅读终点原论文 Introduction/Related Work/Method，必要时查实验、补充、代码和起点论文；保存 URL/材料键、节页、忠实概述或短摘录及核验日。证明有引用的证据不能支持直接继承。

fact 需直接可核证据（至少来自摘要/正文的方法陈述）；AI 比较、仅凭题名关键词或未被作者明确承认的相似性一律用 inference，不得标为 fact。置信度高也不能把推断变事实。已核非 theme 边必须 fact+原始全文位置和核验日期。摘要、综述转述、旧库导入仅 partial/pending；冲突用 disputed。

无法确认则不连边，或 theme 并说明推断依据；保留 pending 技术候选时必须显示状态。不得为图谱丰富强连。大批量从会刊目录新增文献时，应按批次核查新增代表方法与既有基础节点的关系依据，避免新增批次绝大多数沦为孤立点；仍以有据为底线，不凑数。theme 密度不表示继承程度。逆时边应回查预印本/发表日期，不自动翻转。

交付时展示基础、分叉、桥接、融合、孤立并行节点和关键边证据，单列 AI 推断与待核项，供用户浏览后讨论和修订。一般证据缺口不阻断其他整理；影响整体范围或分类体系的关键问题按工作流中的沟通原则处理。
