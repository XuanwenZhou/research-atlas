# 文献整理工作流

输入最小组合是领域说明及可追溯文献来源，先利用已有资料；缺少领域且无法推断才问。时间边界可暂用资料最早年到实际检索日。全文不可读可先用摘要/综述转述并登记缺口。

项目保存 project.json（权威）、search-log.json、review-decisions.json、原始提取材料和 output/。构建仅做确定性转换，不自动检索和推断。

| 环节 | 可审阅产物 | 检查重点 |
|---|---|---|
| 来源 | 领域、综述、时间、可读层级 | 资料足以开展整理 |
| 提取 | 综述分类、方法和带参考编号文献池 | 能追溯读到什么 |
| 整合 | 论文/方法表、重复候选、冲突 | ID 稳定，论文方法分离 |
| 分类 | 一二级体系、定义、跨综述映射 | 覆盖与争议可见 |
| 关系 | 关键边证据表、分支和并行研究 | 关系类型、证据与核验状态一致 |
| 更新 | 方向 × 年份覆盖、查询日志、候选及纳入理由 | 检查相关会刊、引用链和新近分支是否得到检索 |
| 构建 | 方法合集与演进图 | 内容与数据一致、交互可用 |
| 验收 | 数据、浏览器、证据缺口报告 | 分别说明结果 |

按上述环节连续整理并生成 HTML，不将阶段完成作为等待确认的关卡，也不在仅提取少量综述代表作后就暂停询问“是否继续扩充”。多方向大范围整理时，优先编写一次性 Python 检索与去重脚本分批推进（支持子智能体并行时可按一级方向并行检索和精读，再统一合入权威 `project.json`）。常规分类争议保留分类依据、候选归属和不确定性；证据不足的继承候选标为待核或不连边，只有存在同方向依据时才建立 theme 关联。

仅对现有文献无法合理判断、且会显著影响整体研究范围或技术分类体系的关键问题询问用户，说明现有证据、可选处理及影响，并继续处理不受该问题影响的工作。交付时集中呈现分类依据、关键关系证据、未核信息和讨论问题，用户浏览图谱后可继续调整；用户接受某种整理方案不提升其证据等级。

增量：读上次检索日志、覆盖缺口和用户决定。补从上次截止日至今的研究，同时回查近年已搜索但覆盖偏薄的分支。用户要求大范围补充时，按会刊、年份和机制分批检索，汇总后再判断覆盖。用 DOI/arXiv 基础 ID 和标题匹配，只有新记录新建 ID。保存合并映射、原记录、版本及撤回边日志，重新校验专题引用。

专题整理：用户提出具体研究方向或技术主线时，基于现有文献、分类和技术关系细化研究范围，整理核心、代表和补充文献、纳入排除理由及演进路径。在 research_tracks 中保存专题分类、成员和关系，保留已有文献数据库。
